- **EC-01**：[输入超限，如：用户输入超出上下文窗口 → 自动截断最早历史，保留系统提示]

## 8. 非功能需求 (必填)

> 描述系统"做得有多好"（质量约束），与 §7 的行为需求分开。  
> 至少填写可靠性一项；其余按实际约束填写。

- **NFR-01** [性能] [如：端到端响应时间 < 10s（P95），首 token 到达时间 < 2s]
- **NFR-02** [质量] [如：核心场景准确率 > 90%（基于评估数据集），无关拒绝率 < 5%]
- **NFR-03** [成本] [如：单次推理 token 消耗 < 2000（含 system prompt）；或「无特殊成本约束」]
- **NFR-04** [可靠性] [如：任何推理失败必须返回可解析的错误结构，不返回空响应或裸异常信息]

## 9. 验收标准 (必填)

> **与 §5 的关系：** §5 Given/When/Then 描述场景级行为流程（粗粒度）；此处 AC 是系统级可执行检查项（细粒度）。  
> 每条 AC 对应一个 FR 或 EC，写成独立可执行的 pass/fail 判断，不重复场景描述。

- [ ] **AC-NN** *(关联 FR-01)*：[如：输入"天气"，Agent 调用 weather 工具而非直接猜测，推理日志中含工具调用记录]
- [ ] **AC-NN** *(关联 FR-02)*：[如：工具调用成功后，最终响应中引用了工具返回值，未出现幻觉数据]
- [ ] **AC-NN** *(关联 NFR-04)*：[如：LLM 超时时，响应体含 `error.type: "llm_timeout"`，不返回空白]
- [ ] **AC-NN** *(关联 EC-03)*：[如：推理步数超过上限时，返回"已达最大推理步数"提示，不继续循环]
