## 2. 场景和事件叙事

以下为基于材料的**推演**，不是工作坊结果。"当前"指 `leakscan` 已实现的过程（有代码与测试证据，见 implementation-review）；"建议"指本稿提出、尚未实现或未确认的部分。

### 2.1 主流程（当前）

```text
[前置] 员工监控已获批准（BR-004，工具无法自证）
  → 只读账号已发放（网关管理员）
  → 落库现状已探查（probe：内容是否写入、大小、两处存储、认证头、Key 哈希格式）
  → 扫描窗口已选定（安全团队）
  → 调用记录已分批读取
  → 内容已按来源角色拆分
  → 疑似凭证已识别 → 示例/占位值已排除 → 成对/结构已确认 → 本网关 Key 已比对
  → 命中明细已写入（无原文）
  → 覆盖缺口已统计
  → 发现已按"主体 × 凭证"汇总
  → 报告已生成
  → 安全团队已人工研判（工具之外）
  ⋯ 员工已被通知 / 凭证已轮换（阶段 1，不在本闭环）
```

### 2.3 并行、异常与分支

| 分支 | 叙事 | 结果应当是 | 当前实现 |
| :--- | :--- | :--- | :--- |
| 同一私钥被 agent 带进多轮对话 | C04 类：每轮请求都带着历史消息 | 一个发现，调用次数为轮数 | 满足（e2e） |

| 员工贴出同事的网关 Key | C03 / A11 类的内容侧信号 | 标"他人"，不做外部调用 | 满足（合成数据，假定 SHA-256） |
| 共享 / 服务 Key 下的命中 | 一个 Key 由多人或系统使用 | 不能归到某个员工名下 | **未区分**（HS-2，FB-015） |
| Key 关闭了日志 | 内容不落库 | 计入缺口，报告写明 | 满足 |
| 内容超过大小上限 | 长 agent 会话 | 不扫、计缺口、醒目提示 | 满足 |

| 认证头原样落库 | 网关配置问题 | 作为网关系统性问题报告，不逐人计 | 满足 |

## 4. 实质方案取舍

取舍的问题：**回溯审计要回答"员工有没有类似行为"，检测对象到哪里为止？**

| 方案 | 内容 | 业务价值 | 所有权与规则影响 | 成本与误报 | 现有系统影响 |
| :--- | :--- | :--- | :--- | :--- | :--- |
