## 1. 范围与来源

### 1.1 用户决定（原文）

> 1. 新增环境变量形式的密钥规则：变量名以 _TOKEN、_API_KEY、_SECRET、_ACCESS_KEY 结尾，值要够长、熵值够高，并排除 ${VAR} 这类变量引用。
> 2. 新增飞书 t-、u- 开头的 token 规则。
> 3. 用户名是 gitlab+deploy-token-* 这类的，归到 GitLab 令牌。

### 1.2 现状证据（观测，不是业务确认）

对观测样本（9972 行 agent 会话）用修订前规则集 `2026-09-11.1` 扫描，并用独立规则逐行、逐值复查。以下只记录数量、变量名和长度，不记录任何取值。

## 2. 统一语言

| 术语 | 含义 | 区别 |
| :--- | :--- | :--- |
| 环境变量形式的密钥 | 以"变量名 + 赋值"形式出现、变量名表明是密钥、取值本身像密钥的内容 | ≠ 口令字段（第三层 `password_field`，按 `password` 等字段名识别）；≠ 专用格式凭证（如 `glpat-` 前缀，按值本身识别） |
| 变量引用 | 取值指向另一个变量或模板，而不是密钥本身，如 `${VAR}` | 不是凭证，不产生发现 |
| 飞书访问令牌 | 飞书开放平台签发的 `tenant_access_token`（`t-` 开头）和 `user_access_token`（`u-` 开头），有效期短 | ≠ 飞书应用密钥 `app_secret`（长期有效，已有规则） |
| GitLab 部署令牌 | GitLab 为仓库或组签发、用户名形如 `gitlab+deploy-token-<编号>` 的令牌；编号不是秘密 | ≠ 普通账号的 URL 内嵌口令；≠ 以 `gldt-` 开头的新格式部署令牌（已有规则） |
| 规则集候选版本 / 已发布版本 | 候选：规则已修改但尚未通过评估；已发布：可用于出正式审计报告 | "规则写好了"不等于"可以用来出报告" |
| 前后对比 | 同一输入分别用旧、新规则集扫描，列出新增、消失、重新归类的发现 | 对比中出现的新发现是"识别到"，不等于"确认是真实凭证" |

## 3. 业务过程与分支

以下为基于材料的推演。

```text
规则修订已提出（用户，2026-09-11）                        ← 意图
  → 修订已纳入候选规则集（规则维护人）                     ← 受理
  → 合成样本评估已完成（正例全部识别、反例全部不识别）       ← 观测
  → 真实样本前后对比已产出（新增 / 消失 / 重新归类）         ← 观测
  → 候选版本已确认可用于正式审计（安全负责人，BR-009）       ← 承诺
  → 新规则集版本已发布（版本号变化）                        ← 完成（规则集）
  → 已用新版本完成扫描，报告标明版本                        ← 完成（审计使用）
```

| 分支 | 叙事 | 应有结果 | 责任方 |
| :--- | :--- | :--- | :--- |
| 对比出现原有发现消失 | 修订误伤了已有规则 | 候选版本不得用于正式审计；修正或放弃修订 | 规则维护人 |
| 对比新增发现过多 | 阈值过宽导致大量误报 | 不发布；调整阈值后重新对比 | 规则维护人；阈值由安全负责人确认（Q-CLR-01） |
| 扫描进行中发布了新版本 | 旧版本扫描未完成 | 正在进行的扫描按开始时的版本完成；用新程序续扫旧扫描被拒绝 | 运行者 |
| 修订被取消 | 安全负责人不同意 | 已发布版本保持不变 | 安全负责人 |
| 同一值被多条规则识别 | 如 `GITLAB_TOKEN=glpat-…` | 只形成一个发现，按专用类型归类 | 识别规则（BR-015） |
