## 1. 产品概述

### 1.1 一套代码中的两个检查面

完整产品不是只检查端上，也不是只检查网关：

| 检查面 | 入口与用户 | 观测事实 | 能回答的问题 |
| :--- | :--- | :--- | :--- |
| 网关内容检查 | `leakscan`；安全团队 | 网关 PostgreSQL 或导出的 JSONL/JSONL.gz 中的请求、响应、工具内容与请求头 | 哪些经过网关的调用带出了什么凭证、涉及谁、覆盖多少 |
| 端上历史检查 | `leakagent`；本机开发者或经批准的事件响应人员 | Claude Code、Codex 等编码 Agent 已落盘的本地会话 | 绕开网关时是否仍有凭证外泄；是用户粘贴、模型输出还是工具读取；来自哪个文件 |
| 端上实时防护 | 后续实时入口；本机开发者 | Agent 即将执行的工具调用，以及独立 OS 探针观测到的进程和网络行为 | 危险操作能否在执行前阻断/询问；Hook 是否被绕过；Agent 进程树实际执行和连接了什么 |

两条内容检查链共享 `extract → rules → detect`，同一文本和同一规则版本必须得出相同凭证判断。端上与网关的 HMAC 指纹密钥仍不得共用，报告和监管语义也不得混用。

### 1.2 本轮变化

历史会话只能事后回答“发生过什么”。用户现已明确允许把以下能力纳入端上产品：

- 破坏性命令和敏感文件操作的实时 `block / ask / log / allow` 决策；
- 先覆盖编码 Agent 及其子进程树的 EDR 观测，稳定后再单独评审整机 EDR；
- Linux 使用 eBPF/bpftrace 观测 Agent 进程树的 exec、connect 和可验证的流量字节；
- macOS 使用系统 `nettop` 做网络观测；不把它冒充成 exec/EDR 等价实现；
- 将 Hook 事件与 OS 事件关联，发现疑似绕过；
- 故障分级：已知高危操作在必要判定不可用时 fail-closed；未知操作和非关键内部故障 fail-open，但必须留下显著、本地、已脱敏的审计记录。

### 1.3 不变的底线

- 产品自身不向任何网络地址发送报告、遥测、规则、崩溃信息或凭证；“观测到 Agent 连接外部地址”不等于产品自身外发。
- 所有持久化产物均不得含凭证原文、完整环境值或未脱敏的危险命令参数。
- 网关读取始终旁路只读；实时防护只在端上，不改变网关请求处理路径。
- 会话扫描始终不修改、移动或删除 Agent 的会话产物。
- 未经制度告知和批准，不得由 IT 静默统一下发并回收员工级端上审计结果。

### 1.4 可判断的成功

1. 同一合成凭证在网关样本与端上会话中按同一类型、同一规则版本命中，输出均无原文。
2. 已知高危工具调用在执行前被稳定阻断；需要判断的操作交给原生批准界面，未出现重复批准或 blanket allow。
3. 未知工具或非关键审计写入失败不阻塞正常开发，但本地能看到“监测退化”证据；紧急高危规则不可评估时不放行。
4. Linux 真机能区分“Hook 有记录的顶层命令”“仅 OS 探针看到的可疑顶层命令”“合法子进程”；macOS 仅承诺网络事实。
5. 探针未运行、权限不足、平台不支持或解析漂移时明确报告覆盖缺口，绝不以空结果表示安全。

## 2. 目标用户

| 用户角色 | 使用情境与困难 | 核心诉求 |
| :--- | :--- | :--- |
| 开发者（主要端上用户） | 长期开自动批准，不知道 Agent 读了什么、执行了什么、连到哪里；又不能接受监控故障频繁打断正常工作 | 历史可回扫；高危实时拦；不确定操作由自己确认；全部证据只留本机且不含原文 |
| 安全工程师 / 规则维护人 | 同时负责网关与端上检测，担心两套规则漂移；也担心 Hook 被绕过 | 共享凭证规则；策略有版本和正反例；Hook 与系统事实可关联；覆盖缺口可解释 |
| 事件响应人员 | 需要判断一次泄漏是经过网关、端上 Agent，还是绕过 Hook 的子进程造成 | 在网关发现、端上会话、Hook 决策与 OS 观测之间按时间和身份回查 |
| 网关管理员 | 只允许旁路、低影响、只读检查生产数据 | 实时端上能力不得改变网关路径；扫描可限速、可中断、可续扫 |
| 终端安全负责人（整机 EDR 阶段） | Agent 树之外仍可能有风险，但全机采集显著扩大隐私、噪音与运维责任 | Agent 树稳定后再明确授权整机范围、保留期、服务权限和处置责任 |

## 5. 核心业务概念与规则

### 5.1 建模回看

修订 4 的“单角色、无持久状态、无授权，所以纯数据流足够”只适用于历史扫描。实时防护新增了：待执行操作、策略决定、用户批准、运行模式、审计事件、探针事实、关联结果和覆盖状态。它们有身份、时间、竞争与历史，不能继续用一条无状态流水线解释全部产品。

本阶段只记录语义差异，不在 PRODUCT 中确定聚合、数据库、服务或模块：

- 历史网关/端上扫描：多源采集与派生结果，仍按数据流建模；
- 实时决策：一个操作在执行前形成允许/询问/拒绝结果；未来若自建批准服务才会引入并发批准和超时，首版复用 Agent 原生批准界面；
- 系统观测：是“实际发生”的外部事实，不是 Hook 的自述；
- 关联结论：是带置信度的派生判断，不是新的内核事实；
- `/xf-split-v2` 必须据此重新选择方法并验证边界。

### 5.2 数据生命周期

| 数据 | 性质与生命周期 | 原文纪律 |
| :--- | :--- | :--- |
| 网关调用 / Agent 会话 | 外部原始事实，产品只读 | 原文只在读取与内存识别期间存在 |
| 待执行工具事件 | Agent 提供的实时意图，尚未发生 | 策略可临时读取完整输入；持久化前必须脱敏 |
| 策略决定 | 产品在执行前作出的承诺：allow / ask / block / log | 只存规则、原因码、脱敏摘要和键控哈希 |
| OS 观测事件 | 探针观察到的 exec/connect/bytes 事实 | 不落完整 argv、环境或载荷；仅存脱敏摘要和必要元数据 |
| 关联结果 | Hook 与 OS 事实的派生判断 | 必须带状态与置信度；可随算法重算，不改写原始决定 |
| 覆盖状态 | 探针是否运行、权限和平台能力 | 空数据必须与“没有观测能力”区分 |
| 历史发现 / 报告 | 从命中与覆盖派生 | 不含凭证原文，可重算 |

### 5.3 容易混淆的概念

| 概念 | 含义 | 不等于 |
| :--- | :--- | :--- |
| 产品外发 | 本产品主动向外部地址传输数据 | Agent 被观测到的外连；后者是审计对象 |
| 操作意图 | Hook 在执行前收到的工具输入 | OS 探针看到的已执行事实 |
| block | 产品明确拒绝本次操作 | ask 后用户拒绝；两者原因和责任不同 |
| ask | 交还用户/Agent 原生批准界面决定 | 默认允许；没有回答不得伪造批准 |
| 监测退化 | 某层故障、未知或不可用 | “没有风险”；必须成为覆盖缺口或显著事件 |
| Hook 绕过疑似 | 高置信顶层 OS 执行无法与 Hook 意图关联 | 每个无 Hook 记录的子进程；后者通常是合法派生 |
| Agent 树 EDR | 只观察选定编码 Agent 及其后代 | 整机 EDR；后者默认关闭并需另行批准 |
| 端上审计日志 | 本地、脱敏的安全事实 | Agent transcript；不得复制完整对话或工具结果 |

### 5.4 业务规则

## 6. 产品边界

### 本轮纳入

- 网关历史内容检查和本地导出文件检查继续保留，仍为安全团队旁路只读工具（网关产品定义见 ESRC-012，不被本轮取代）。
- 端上历史会话内容/行为检查继续保留。
- Claude Code 等具备 Hook/插件机制的 Agent 可接入实时策略；没有机制的 Agent 只提供历史与系统观测，不能假装可拦截。
- 破坏性命令、提权、持久化、反弹 shell、数据库破坏、容器逃逸、监测篡改、敏感文件和凭证搜刮进入端上策略范围。
- Linux Agent 进程树 eBPF 与 macOS Agent 进程树网络观测进入规划范围。
- 整机 EDR 是明确的后续阶段，不再永久排除，但默认关闭且不由本轮自动扩大。

### 仍不做或暂不承诺

- 不上传、不建云端控制台、不集中收集员工端日志；若以后改变，必须重新做 EBR-004 评审。
- 不读取网络载荷、不做 TLS MITM、不安装 CA、不把目的 IP 交第三方查询。
- 不宣称 macOS `nettop` 能看到 exec、域名或代理后的真实目的地。
- 不宣称 Windows 已具备 ETW/Sysmon/WFP 观测；需真机与权威设计后再确定。
- 不宣称 macOS 已具备 Endpoint Security exec 遥测；其签名、entitlement 和 Full Disk Access 均未取得证据。
- 不自动评价员工、不做绩效/纪律风险分；策略事件只描述操作和技术风险。
- 首个实时版本不建设远程 Web UI 或自有批准服务，优先复用 Agent 原生批准界面。

## 9. 修订影响与交接

### 9.1 被本轮取代的旧结论

- 修订 4 的“只读历史产品、不实时、不能拦截”仅保留为历史扫描入口的事实，不再是整体产品边界。
- “不做内核层观测”“不做 EDR”“ECAP-010 不在本版”已被 ESRC-015 明确改变。
- “CC-Monitor 无许可证、33 条规则、30 条 EDR 不纳入”已被当前本地证据取代：MIT、70 条，且用户允许纳入相关能力。
- “不改 Agent 任何配置”改为“会话源只读；Hook 安装对指定配置做受控、可逆、幂等修改”。
- “三平台静态二进制 = 三平台功能相同”仍然错误；可选探针按平台分别验收。

### 9.2 对既有实现的影响

- `leakscan` 网关只读扫描不需要因本轮改变行为。
- `leakagent` 历史扫描继续保留；现有 `behavior.csv` 可作为策略 shadow 的输入/输出基础，但 7 条无状态检测规则不足以直接承担实时拦截。
- 需要新增实时入口与本地审计职责；具体二进制、包、存储和协议由 split/design 决定，本文不提前指定。
- 内容规则集仍只有一份；行为策略必须独立版本化，避免把策略变化误写成凭证规则变化。

### 9.3 下一步

本次能力、规则、外部权威和范围均发生实质变化，原模块依据状态为**需复核**。可继续执行 `/xf-split-v2`，随后再形成实时策略、Hook、审计、探针和关联的需求/设计/任务。未完成这些步骤前，不应直接把 70 条规则或探针代码批量塞入现有 `internal/behavior`。
