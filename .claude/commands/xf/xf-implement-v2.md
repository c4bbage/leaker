# xf-implement-v2：实现对照核验

命令版本 2.2.0。本命令核验实现，不启动第二条编码流程。

## 用户输入

```text
$ARGUMENTS
```

## 共同约定

执行前读取 `.opencode/command-resources/product-split-v2/` 下的 `downstream.md`、`downstream-templates.md`、`downstream-checklist.md`。

只写 `xspec/xf/v2/implementation-review.md`、`feedback.md`。不修改业务代码或正式制品，不调用生产控制面或正式阶段脚本。实际代码变更由原 `/xf-implement` 在其既有前置与门禁下执行，本命令不代替它。

## 执行

1. 读取 PRODUCT、选定需求与 EX、architecture、detail、tasks 及报告和 feedback；选择本轮 JOB / DES / EX，检查基线是否有效。缺上游只记录可确定证据，不造已完成设计。
2. 先用 rg 查找对应代码、接口和测试，再阅读实际行为；记录审查范围、文件内容摘要及代码版本。工作区未提交内容用实际文件摘要定位，不能仅记 HEAD。
3. 检查责任归属、写入路径、聚合/事务、命令结果、事件消费及恢复是否符合有效设计。重点查 EX 的正常与异常结果，而非是否存在同名类或函数。
4. 区分测试定义、实际运行和外部集成证据。运行前确认测试不触达生产、不会迁移/删除真实数据；本地测试按与本次规则相关的最小范围执行。记录命令、退出码、环境和实际结果；无法运行就写未验证和原因。
5. 发现代码与设计差异时判断：实现缺陷、设计假设不成立，还是业务规则已变。feedback 指向相应层次并引用反例；不修改设计来掩盖缺陷，也不以核验授权替代编码流程。
6. 写 implementation-review，逐项检查 I01–I05、G01–G06。结论使用已验证/发现差异/未验证，限定到实际检查的 JOB / EX；Mock 不证明外部系统保证，全量产品验收不能从局部测试推出。

## 完成报告

提供核验报告，列出实际查验/运行内容、结果、缺口和反馈。需要修复代码时给出可交接的具体问题及文件位置；独立核验完成不表示实施任务完成或正式阶段通过。
