# xf-task-v2：任务与验证计划

命令版本 2.2.0。

## 用户输入

```text
$ARGUMENTS
```

## 共同约定

执行前读取 `.opencode/command-resources/product-split-v2/` 下的 `downstream.md`、`downstream-templates.md`、`downstream-checklist.md`。

只写 `xspec/xf/v2/tasks.md`、`tasks-review.md`、`feedback.md`。JOB 是独立任务标识，不向正式 task、change 或索引写入。

## 执行

1. 读取 PRODUCT、选定需求与 EX、architecture、detail、各自报告及 feedback，核实摘要与技术可行范围。不能把无效基线修饰成可执行任务。
2. 按可验证的业务闭环拆 JOB，每项给交付结果、实际或建议文件范围、DES / REQ / EX、前置和验证办法。文件路径尚未落地时标“建议”，不谎称已经存在。
3. 将实现、必要的持久化/并发验证、外部契约核对和集成验收纳入任务。简单文案或可逆低影响调整不为凑覆盖写镜像测试；复杂不变量需要与风险相称的验证。
4. 检查前置 JOB 是否存在及无环；跨模块协作标明消费/提供契约。业务事件闭环不是任务依赖循环。没有依据不填写工期和负责人。
5. 设计前提未解决的生产实施项标不可执行并引用反馈。可以安排不依赖该前提的资料核对项；不能把已知技术未知包装成“先实现再验证”。
6. 写正式实施交接：业务及模块差异、独立 ID 到正式制品的待映射范围、需要采用的设计决定。正式 ID 和门禁由原流程管理，不伪造映射已完成。
7. 重新读盘检查 T01–T05、G01–G06，报告任务范围、设计摘要、覆盖和不可执行项。无实际代码证据不标任务完成。

## 完成报告

提供任务与报告链接，说明可交接闭环、前置依赖、异常验收覆盖和未满足条件。可用 xf-implement-v2 做实现对照核验；实际编码通过现有正式实施流程。
