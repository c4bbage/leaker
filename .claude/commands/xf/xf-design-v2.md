# xf-design-v2：架构与领域设计

命令版本 2.2.0。

## 用户输入

```text
$ARGUMENTS
```

## 共同约定

执行前读取 `.opencode/command-resources/product-split-v2/` 下的 `downstream.md`、`downstream-templates.md`、`downstream-checklist.md` 和 `eventstorming.md`。

只写 `xspec/xf/v2/architecture.md`、`architecture-review.md`、`feedback.md`。本命令生成独立设计评审稿，不替代正式 xf-design 或其前置审批。

## 执行

1. 按共同约定读取 PRODUCT、split-review、选定的 requirements 或合格 exploration、已有反馈和本轮相关代码/契约。核对范围、上游 SHA-256 和来源；失效结论先复核。
2. 读取 PRODUCT 的设计交接与回看条件。复查上下文语言、模块映射、事实所有权及查询/命令/事件关系，不将原拆分直接当最终聚合设计。
3. 对复杂业务围绕 BR 推导聚合候选、实体身份、值对象及行为。逐项解释不变量由哪个有界责任单元保护；跨聚合约束明确仲裁者、协调方式及失败补偿。禁止仅列 DDD 类名、无限聚合或独立快照写入。
4. 对每个关键 DES 说明需求/验收依据、选型理由、原子性范围与外部前提。同步/异步及持久化形式按需要选择，不因发现业务事件默认消息总线或事件溯源。简单能力可直接用模块职责和事务方案。
5. 核实外部系统实际控制权、接口与版本。本地期望端口和外部已有能力分开；影响当前可行性的技术问题当场查证或做有边界的 PoC。缺少不可取得的外部证据时相关方案保持候选，禁止标可实施。
6. 用 EX 回放正常与关键异常，特别检查并发竞争、持久化与外部副作用之间的失败窗口。需改变产品/拆分时写 feedback，停止依赖失效前提的结论，保留独立可成立部分。
7. 写 architecture 和向 detail 的输入：DES、模型与 BR、协作契约、需要精化的状态/事务及验收办法。重新读盘执行 D01–D06、G01–G06，报告区分文档自检与技术可行性。

## 完成报告

说明聚合/责任边界为什么成立、哪些已有证据、哪些仅为候选、反例反馈和可进入详细设计的范围。提供设计及报告链接；不称独立稿已获正式批准。
