管理 `xspec/TECH-DEBT.md` 技术债务清单，支持添加债务、偿还债务、查看债务操作。

## 用户输入

```
$ARGUMENTS
```

**参数解析**：

- **无参数**：列出当前技术债务摘要（等同于 `list`）
- **子步骤**：`add` / `resolve` / `list`

**参数表**：

| 参数 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `--title` | string | add 时必填 | 债务标题 |
| `--pri` | string | add 时必填 | 优先级：`high` / `medium` / `low`（对应 🔴 / 🟡 / 🟢） |
| `--ver` | string | add 时必填 | 目标版本号（如 v1.4.0） |
| `--module` | string | add 时可选 | 所属模块（如 004-aiderag-integration） |
| `--from` | string | add 时可选 | 来源（如 CHG-20260424-004） |
| `--workload` | string | add 时可选 | 工作量估算（如 ~3 天、~2 周） |
| `--doc` | string | add 时可选 | 文档位置（如 modules/004/P0-APPROXIMATIONS.md § 1） |
| `--task` | string | add 时可选 | 任务编号（如 T068） |
| `--resolve` | string | resolve 时必填 | 债务编号（如 D-001） |

## 前置条件

- `xspec/TECH-DEBT.md` 必须存在

---

## 步骤 1：参数解析与目标文件确定

### 1.1 解析子步骤

根据用户输入识别子步骤：
- 包含 `add` 或 `--add` → `add`
- 包含 `resolve` 或 `--resolve` → `resolve`
- 包含 `list` 或无参数 → `list`

### 1.2 确定目标文件

**目标文件**：始终为 `xspec/TECH-DEBT.md`

---

## 步骤 2：执行子步骤操作

### 2.1 add（添加技术债务）

**用法**：
```bash
/xf:debt add --title "实时 BM25 分数" --pri high --ver v1.5.0 --module 004-aiderag-integration --from "CHG-20260424-004" --workload "~3 天"
```

**实现步骤**：

1. **读取 TECH-DEBT.md**

2. **分配债务编号**：
   - 扫描现有债务编号（格式：`#### D-XXX`）
   - 查找最大编号（如 D-018）
   - 递增生成新编号（D-019）

3. **生成债务条目**：

```markdown
#### D-{NNN} {债务标题}
- **当前状态**：{描述当前实现方式}
- **影响**：{描述对系统的影响}
- **目标版本**：{version}
- **所属模块**：{module}（如果提供）
- **来源**：{from}（如果提供）
- **工作量**：{workload}（如果提供）
- **状态**：⏳待偿还
- **文档位置**：{doc}（如果提供）
- **任务编号**：{task}（如果提供）
```

4. **插入到对应优先级区块**：
   - `--pri high` → `### 🔴 高优先级（P1 必须解决）`
   - `--pri medium` → `### 🟡 中优先级（P2 应该解决）`
   - `--pri low` → `### 🟢 低优先级（P3 可以解决）`

5. **更新统计信息**：
   - 更新第 4 行：`> 总计：N 项（🔴高 X / 🟡中 Y / 🟢低 Z）`
   - 更新第 3 行：`> 最后更新：{当前日期 YYYY-MM-DD}`

6. **输出确认**：
```
✅ 添加技术债务：D-{NNN} {债务标题}
  - 优先级：{🔴高 / 🟡中 / 🟢低}
  - 目标版本：{version}
  - 债务编号：D-{NNN}
```

---

### 2.2 resolve（偿还技术债务）

**用法**：
```bash
/xf:debt resolve --resolve D-001
```

**实现步骤**：

1. **读取 TECH-DEBT.md**

2. **查找债务编号**：
   - 搜索 `#### D-{NNN}` 锚点
   - 如果未找到，报错：`❌ 未找到债务编号：D-{NNN}`

3. **更新债务状态**：
   - 查找该债务条目中的 `- **状态**：⏳待偿还` 行
   - 替换为：`- **状态**：✅已偿还（{当前日期 YYYY-MM-DD}）`

4. **更新统计信息**：
   - 扫描所有债务条目，统计各优先级的待偿还数量
   - 更新第 4 行：`> 总计：N 项（🔴高 X / 🟡中 Y / 🟢低 Z）`
   - 更新第 3 行：`> 最后更新：{当前日期 YYYY-MM-DD}`

5. **输出确认**：
```
✅ 偿还技术债务：D-{NNN} {债务标题}
  - 偿还日期：{当前日期 YYYY-MM-DD}
  - 剩余债务：{剩余待偿还总数} 项
```

---

### 2.3 list（查看技术债务）

**用法**：
```bash
/xf:debt list
```

**实现步骤**：

1. **读取 TECH-DEBT.md**

2. **解析债务统计**：
   - 提取第 4 行统计信息：`> 总计：N 项（🔴高 X / 🟡中 Y / 🟢低 Z）`
   - 提取第 3 行更新日期

3. **输出摘要**：
```
📋 技术债务清单（最后更新：{日期}）

**总计**：{N} 项（🔴高 {X} / 🟡中 {Y} / 🟢低 {Z}）

**🔴 高优先级（P1 必须解决）**：
  - D-001: 实时 BM25 分数 → v1.5.0（~3 天）⏳
  - D-002: 多用户并发控制 → v1.4.0（~2 周）⏳

**🟡 中优先级（P2 应该解决）**：
  - D-010: 查询参数验证 → v1.4.0（~3 天）⏳

**🟢 低优先级（P3 可以解决）**：
  - D-017: 优化 SQLite 索引 → v1.6.0（~1 周）⏳

**已偿还**：
  - D-XXX: {债务标题} ✅（2026-05-01）
```

---

## 行为规则

1. **债务编号唯一性**：自动递增，确保不重复
2. **优先级映射**：
   - `high` / `p1` / `🔴` → 🔴 高优先级
   - `medium` / `p2` / `🟡` → 🟡 中优先级
   - `low` / `p3` / `🟢` → 🟢 低优先级
3. **日期格式**：始终使用 `YYYY-MM-DD` 格式
4. **状态标记**：
   - 待偿还：⏳
   - 已偿还：✅（含日期）

---

## 错误处理

| 错误情况 | 处理方式 |
|:---|:---|
| TECH-DEBT.md 不存在 | 输出：`❌ 错误：xspec/TECH-DEBT.md 不存在`<br>提示：`请先创建技术债务清单文件` |
| add 参数缺失 | 输出：`❌ 错误：add 子步骤需要 --title, --pri, --ver 参数`<br>示例：`/xf:debt add --title "债务名" --pri high --ver v1.5.0` |
| resolve 债务编号未找到 | 输出：`❌ 错误：未找到债务编号：{id}`<br>提示：`请使用 /xf:debt list 查看所有债务编号` |
| 优先级无效 | 输出：`❌ 错误：无效的优先级：{输入值}`<br>提示：`请使用 high / medium / low（或 p1 / p2 / p3）` |
