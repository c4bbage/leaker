管理 `xspec/BACKLOG.md` 功能池（Feature Backlog），支持添加需求、废弃需求、查看需求操作。

## 用户输入

```
$ARGUMENTS
```

**参数解析**：

- **无参数**：列出当前功能池摘要（等同于 `list`）
- **子步骤**：`add` / `deprecate` / `list`

**参数表**：

| 参数 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `--title` | string | add 时必填 | 功能标题 |
| `--desc` | string | add 时必填 | 功能描述（1-2 句话） |
| `--pri` | string | add 时必填 | 优先级：`P0` / `P1` / `P2` / `P3` / `P2+`（P2+ 表示接近 P1） |
| `--tags` | string | add 时必填 | 标签（逗号分隔，如 `export,manager` 或 `viewer,ui`） |
| `--id` | string | deprecate 时必填 | 功能编号（如 `B-001`） |
| `--reason` | string | deprecate 时必填 | 废弃原因（如「已合并到其他需求」「不再符合产品方向」） |

## 前置条件

- `xspec/BACKLOG.md` 必须存在

---

## 步骤 1：参数解析与目标文件确定

### 1.1 解析子步骤

根据用户输入识别子步骤：
- 包含 `add` 或 `--add` → `add`
- 包含 `deprecate` 或 `--deprecate` → `deprecate`
- 包含 `list` 或无参数 → `list`

### 1.2 确定目标文件

**目标文件**：始终为 `xspec/BACKLOG.md`

---

## 步骤 2：执行子步骤操作

### 2.1 add（添加功能需求）

**用法**：
```bash
/xf:backlog add --title "知识导出功能" --desc "支持将知识库导出为 JSON/Markdown/CSV 格式，便于备份和迁移" --pri P2 --tags "export,manager"
```

**实现步骤**：

1. **读取 BACKLOG.md**

2. **分配功能编号**：
   - 扫描「待规划」表格中的编号（格式：`B-XXX`）
   - 查找最大编号（如 `B-018`）
   - 递增生成新编号（`B-019`）

3. **生成功能条目**：

```markdown
| B-{NNN} | {title} | {desc} | {pri} | {tags} | {YYYY-MM-DD} |
```

4. **插入到「待规划」表格**：
   - 在表格最后一行（`---` 之前）插入新条目
   - 保持对齐格式

5. **更新统计信息**：
   - 递增「条目数」计数（第 4 行 `> 条目数：N`）
   - 更新「最后更新」日期（第 3 行 `> 最后更新：YYYY-MM-DD`）

6. **输出确认信息**：

```
✅ 功能需求已添加：B-{NNN} {title}

📋 需求信息：
- 编号：B-{NNN}
- 标题：{title}
- 描述：{desc}
- 优先级：{pri}
- 标签：{tags}
- 添加日期：{YYYY-MM-DD}

当前功能池：{总条目数} 条（P0: {count}, P1: {count}, P2: {count}, P3: {count}）
```

---

### 2.2 deprecate（废弃功能需求）

**用法**：
```bash
/xf:backlog deprecate --id B-005 --reason "已合并到 B-018 研究课题功能"
```

**实现步骤**：

1. **读取 BACKLOG.md**

2. **查找目标条目**：
   - 在「待规划」表格中搜索 `| B-{id} |`
   - 如果未找到 → 报错：`❌ 功能需求 B-{id} 不存在于待规划列表`

3. **提取条目信息**：
   - 标题（第 2 列）
   - 添加日期（第 6 列）

4. **从「待规划」表格删除该行**

5. **插入到「已废弃」表格**：

```markdown
| B-{id} | {title} | {reason} | {添加日期} | {YYYY-MM-DD} |
```

6. **更新统计信息**：
   - 递减「条目数」计数
   - 更新「最后更新」日期

7. **输出确认信息**：

```
✅ 功能需求已废弃：B-{id} {title}

📋 废弃信息：
- 编号：B-{id}
- 标题：{title}
- 原因：{reason}
- 废弃日期：{YYYY-MM-DD}

当前功能池：{总条目数} 条（P0: {count}, P1: {count}, P2: {count}, P3: {count}）
```

---

### 2.3 list（查看功能池摘要）

**用法**：
```bash
/xf:backlog
/xf:backlog list
```

**实现步骤**：

1. **读取 BACKLOG.md**

2. **统计分析**：
   - 总条目数（第 4 行提取）
   - 按优先级分组统计：P0 / P1 / P2 / P2+ / P3
   - 按标签分组统计：top 5 标签及其出现次数
   - 最新添加的 5 条需求（按添加日期倒序）
   - 已废弃条目数

3. **输出摘要**：

```
📋 功能池摘要（最后更新：YYYY-MM-DD）

📊 统计：
- 总条目数：{N} 条
- 优先级分布：P0({n}) P1({n}) P2({n}) P2+({n}) P3({n})
- 已废弃：{n} 条

🏷️  热门标签（Top 5）：
1. viewer (8 条)
2. manager (7 条)
3. ui (5 条)
4. search (3 条)
5. i18n (2 条)

🆕 最新添加（最近 5 条）：
- B-018 研究课题（Research Topic） [P2, 2026-05-08]
- B-017 全面异步化 [P2, 2026-05-07]
- B-016 PostgreSQL 存储引擎 [P2+, 2026-05-07]
- B-015 知识推荐引擎 [P2, 2026-05-06]
- B-014 实时协作编辑 [P3, 2026-05-06]

💡 提示：
- 添加需求：/xf:backlog add --title "..." --desc "..." --pri P2 --tags "tag1,tag2"
- 废弃需求：/xf:backlog deprecate --id B-XXX --reason "..."
```

## 步骤 3：输出与验证

### 3.1 文件写入

将修改后的内容写入 `xspec/BACKLOG.md`。

### 3.2 最终输出

根据子步骤返回对应的确认信息（见上文各子步骤的「输出」部分）。

## 交互规则

- 当 `--pri` 参数不在允许列表时（`P0|P1|P2|P2+|P3`），使用 `question` 工具询问用户选择正确的优先级
- 当 `--tags` 参数为空或格式不正确时，提示用户提供至少一个标签（逗号分隔）
- 当 `deprecate` 的 `--id` 不存在时，列出当前所有待规划的功能编号供用户参考

---

## 注意事项

1. **编号唯一性**：功能编号 `B-XXX` 全局唯一，即使废弃后也不会被复用
2. **优先级约定**：
   - **P0**：核心功能缺失，严重影响产品可用性
   - **P1**：重要功能，影响主要使用场景
   - **P2**：改善体验，增加竞争力
   - **P2+**：介于 P1 和 P2 之间，接近 P1 优先级
   - **P3**：锦上添花，长期规划
3. **标签约定**：
   - **模块标签**：`viewer`、`manager`、`storage`、`search`、`api`、`domain`
   - **功能标签**：`ui`、`export`、`viz`、`feedback`、`notify`、`i18n`、`mobile`、`realtime`、`ai`、`performance`、`enterprise`
4. **与 ROADMAP 的关系**：
   - BACKLOG 是**功能池**（未规划的想法和需求）
   - ROADMAP 是**路线图**（已规划到版本的功能）
   - 从 BACKLOG 提升到 ROADMAP：使用 `/xf:roadmap plan --add "..." --pri P1 --ver v1.5`
5. **与 TECH-DEBT 的区别**：
   - BACKLOG 是**新功能需求**（增量）
   - TECH-DEBT 是**技术债务**（现有实现的改进点）

- 标题：知识全文索引
- 描述：支持 FTS5 全文搜索，替代当前的 BM25 实现
- 优先级：P1
- 标签：search,performance
- 添加日期：2026-05-09
