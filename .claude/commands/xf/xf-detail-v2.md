# xf-detail-v2：详细设计

命令版本 2.2.0。

## 用户输入

```text
$ARGUMENTS
```

## 共同约定

执行前读取 `.opencode/command-resources/product-split-v2/` 下的 `downstream.md`、`downstream-templates.md`、`downstream-checklist.md`。

只写 `xspec/xf/v2/detail.md`、`detail-review.md`、`feedback.md`。不生成正式 change 制品，不运行正式阶段和审批操作。

## 执行

1. 读取 PRODUCT、选定需求与 EX、architecture 及报告、已有 feedback 和实际相关代码/接口。按摘要识别变更，声明本轮可细化范围；上游仍为候选的部分不能因细化而自动变成已验证。
2. 按 DES 定义所需数据与持久化模型、身份/版本/有效期及唯一写入入口；明确主数据、配置、观测、承诺和日志之间的关联。聚合与表的映射说明业务理由，不机械一一对应。
3. 定义必要命令、查询与跨边界事件契约，逐项写请求身份、授权上下文、版本前置、返回语义、幂等范围、顺序与时效。明确外部实际接口与本地期望端口的区别。
4. 按具体对象列状态转换与守卫，区分命令受理、执行结果、实际就绪。覆盖相关的重复、竞争、超时、迟到、取消、重启和人工恢复；未知状态有查询/对账责任与解除条件。
5. 写清事务范围、并发裁决、持久化与外部调用之间的失败窗口及恢复方法。若采用 outbox、锁或租约，解释保证及局限，不能只写技术名词；验证权威端是否支持要求的机制。
6. 将每个 EX 映射到验证层次、输入、预期结果和环境需求。技术不确定性在设计阶段查证；无法兑现的前提写 feedback 回 design/split，相关部分不交给生产实施。
7. 按模板写 detail，重新读盘执行 L01–L06、G01–G06。报告列出可交接任务的范围、候选部分、技术证据和上游摘要。

## 完成报告

提供详细设计与报告链接，说明关键事务/状态/恢复选择、验收映射、自检和不可交接范围。禁止把状态表齐全等同于方案可实施。
